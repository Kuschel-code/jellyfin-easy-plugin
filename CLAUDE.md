# Easy Plugin — Jellyfin admin sidebar organiser

Jellyfin 10.11.x / .NET 9 plugin that hides, reorders, groups and renames plugin entries in
the admin sidebar, and opens any plugin's settings inline. Plugin GUID
`f4acffe0-0347-4b20-a69d-d50d6b2b4a7e`.

`README.md` explains the mechanism (client-side DOM + in-memory `index.html` injection via a
File Transformation provider) and the caveats. Read it before changing how injection works.
This file is the map.

## Commands

```bash
dotnet build Jellyfin.Plugin.EasyPlugin/Jellyfin.Plugin.EasyPlugin.csproj -c Release
dotnet test
cd web-tests && npm ci && npm test      # node --test + jsdom, the browser-side half
```

Most of the behaviour lives in the browser, so a green `dotnet test` proves very little on
its own. `web-tests/` is the suite that actually covers sidebar ordering, grouping,
renaming, filtering and the config page's save round-trip.

## Layout

`Jellyfin.Plugin.EasyPlugin/` — `Web/client.js` (the injected script, most of the logic),
`Configuration/configPage.html` (the settings page), plus the plugin and API classes.
`Jellyfin.Plugin.EasyPlugin.Tests/` is the xUnit side, `web-tests/` the jsdom side.

## Things that will bite you

- **The version lives in two files.** `AssemblyVersion` *and* `FileVersion` in the `.csproj`,
  and `version` in `Jellyfin.Plugin.EasyPlugin/build.yaml` (which also holds the changelog).
  Bump both, then tag — the release is a tag push, not a workflow button.
- **`manifest.json` is written by the release workflow**, not by hand
  (`.github/scripts/update-manifest.py`). Jellyfin verifies the checksum before installing,
  so an entry that doesn't match the published zip makes that version **un-installable** —
  0.0.4 and 0.0.6 both broke exactly that way while the manifest was maintained manually.
  Re-running a release rebuilds the artifact and can change the checksum, which is why the
  workflow rewrites the entry rather than trusting it.
- **The DLL embeds *minified copies* of `Web/client.js` and `Configuration/configPage.html`,**
  generated by an inline MSBuild task into `$(IntermediateOutputPath)ep/`. Edit the source
  files — never the intermediates. The minifier is deliberately naive: it trims every line,
  drops blank lines, and only removes a `/* */` comment when it opens and closes on the same
  line. That is why each web-test suite runs the code **twice**, as written and as minified;
  a construct the minifier would mangle shows up there and nowhere else. Don't skip them.
- **`EpMaxDllBytes` (45,056) is an advisory warning, not a gate.** It came from one server
  reported to corrupt the DLL at offset 0xB000. The budget has been exceeded since 0.0.5
  with no recurrence, so a warning here is a decision to make, not a build failure to
  "fix" by raising the number without reading the note in the `.csproj`.
- **The sidebar selectors are pinned to jellyfin-web 10.11**: the `plugins-subheader` list
  id and the `#/configurationpage?name=` href format. A future web build that renames either
  makes the plugin do nothing at all, with no error — check `Web/client.js` first when
  "it stopped working" after a server update.
- **Only `/EasyPlugin/ClientScript` is anonymous.** A `<script src>` tag carries no
  credentials, so the script file must be public; the layout endpoint requires a signed-in
  caller and the script borrows the web app's access token. Before sign-in there is no
  token and the sidebar is simply left untouched — that is correct behaviour, not a bug.
- **There is no on-disk fallback, by design.** The container's jellyfin-web is typically
  read-only; injection goes through a File Transformation provider or not at all.
- **Hiding and reordering are CSS; renaming, groups and the filter box are DOM edits**
  re-applied on every mutation. The CSS half survives React re-renders, the DOM half is the
  fragile one — prefer expressing a new feature as CSS when there is a choice.
